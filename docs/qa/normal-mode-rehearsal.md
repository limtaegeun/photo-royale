# QA TC — 일반전 종합 리허설 (normal-mode-rehearsal)

- **대상**: 배포본 `https://photo-royale-scc.web.app` (main `463af98`) — 브랜치 작업이 아니라 **출시 상태 그대로**의 종합 검증
- **작성·실행일**: 2026-08-31 (`qa-flow`: qa-tc → live-qa)
- **크리티컬리티**: 오프라인 이벤트 당일 실시간 게임 — **장애 허용 불가**. 이 문서는 개별 기능 TC가 아니라
  당일 타임라인을 그대로 이어 붙인 **P0 리허설 체인**이다. 개별 기능 TC는 아래 선행 문서들이 소유한다.
- **후속**: 이 리허설의 P1(N군)은 **PR #30 진행자 강퇴로 해소**됐다(2026-09-06 머지·배포). 아래 N군 판정은
  **해소 전 상태의 기록**이며, 강퇴 자체의 검증은 `waiting-room.md`의 Q군·J-08이 소유한다.
- **선행 문서**: `waiting-room.md` · `team-assignment.md` · `camera-cockpit.md` ·
  `photo-submission-judging.md` · `round-ops.md` · `record-review.md`
- **실행 방법**: 실계정 13개(호스트 1 + 참가자 13)로 배포본에서 8차 라운드까지 연속 진행.
  화면 조작은 브라우저(chrome-devtools MCP), 대량 동시 입력과 서버 규칙 검증은 Firestore REST.

## 이 리허설이 답하려는 질문

1. 일반전 외 게임 모드는 정말 잠겨 있는가 — 화면과 서버 양쪽에서
2. 일반전 한 판이 방 만들기부터 라운드 종료·다음 라운드 배정까지 끊기지 않고 돌아가는가
3. 실사용에서만 드러나는 것(홀수 인원, 참가자 제외, 지각 합류, 응답 없는 참가자)에서 무너지지 않는가

## 당일 운영 체크리스트 — 이 리허설에서 나온 것

1. **배정 확정 전에 준비 인원 수를 눈으로 센다.** `N명 입장 · N명 준비`가 같아야 배정 보드가 열린다.
2. **응답 없는 사람은 명단에서 눌러 내보낸다**(PR #30). 내보내면 남은 인원만으로 배정이 열리고,
   그 사람이 돌아오면 같은 초대 코드로 다시 들어올 수 있다 — 다만 짝꿍 이력은 처음부터 다시 쌓인다.
3. **이번 라운드만 쉬게 하려면 내보내지 말고** 배정 보드에서 미배정 대기자로 옮긴다. 이때는
   그 사람이 준비를 누른 뒤여야 보드가 열린다.
4. **제외한 사람에게는 진행자가 직접 말로 알린다.** 앱은 그 사람에게 아무것도 알리지 않고 `팀 확인 중`만 보여준다(X-02).

## 알려진 한계 (버그 아님)

- 라운드 1의 미판정 킬샷 3건은 다음 라운드 판정 큐에 나오지 않는다 — 판정은 현재 차수만 대상이다(기록 탭에는 `대기`로 남는다).
- 아이템·지도·기록 HUD 버튼은 비활성이다(미구현).
- 제외자의 `team` 필드는 서버에서 지워지지 않는다 — `assignedRound` 차수 마커로 걸러내는 것이 설계다(`isAssignedInRound`).
