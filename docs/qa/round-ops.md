# 라운드 운영(round-ops) QA Test Case

- **브랜치**: `feat/p02-team-assignment` (미커밋 변경분 + untracked 신규 feature 포함)
- **작성일**: 2026-07-25 / **live-qa 실검증**: 2026-07-25 (local dev `http://localhost:5174`, Chrome for Testing 3 프로파일)
- **크리티컬리티**: 오프라인 이벤트 당일 실시간 진행 — **장애 허용 불가**. 호스트 기기는 진행 지휘 단일 지점이라, 이 화면이 죽으면 게임 자체가 멈춘다.
- **검증 결과 요약**: 50 TC 중 **✅ 41 / ⚠️ 6(부분) / ⏸ 3(미검증)**. P0-01 풀체인 통과. 상세는 §15.
- **선행 문서**: [waiting-room.md](./waiting-room.md) (게임 시작 전이 TC I군과 연계), [team-assignment.md](./team-assignment.md)

> **이번 작업의 본질**: 호스트는 플레이어가 아니라 진행자다. 그런데 게임 시작 시 전원이 `/camera`로 갔기 때문에 호스트 기기에도 카메라 콕핏 + 권한 프롬프트가 떴다. 이번 변경은 **호스트만 `/round-ops/:roomCode`로 갈라지게** 하고, 그 화면을 **동작 없는 골격(스켈레톤)** 으로 세운 것이다. 따라서 QA의 1순위는 "운영 기능이 되는가"가 아니라 **"전이가 역할별로 정확히 갈리는가 + 스켈레톤이 오해를 유발하지 않는가"** 다.

## 13. 당일 운영 체크리스트 (round-ops 관련)

0. **🔴 배포 순서 주의**: `firestore.rules`를 앱과 **함께 배포**해야 한다. 이번 QA에서 배포된 ruleset이 구버전(`participants`의 `assignedRound` 갈래 없음)이어서 **앱의 `배정 확정`이 403으로 전부 실패**했다(배포 후 즉시 정상). 이벤트 전 스모크에 "배정 확정 1회 성공"을 반드시 포함한다.
1. **시작 전 스모크**: 테스트 방으로 호스트 폰에서 `게임 시작` → 라운드 운영 화면 진입 + **카메라 권한 프롬프트 없음** 확인. 프롬프트가 뜨면 구버전 배포이므로 **시작 보류**.
2. **호스트 폰 새로고침 확인**: `/round-ops/{코드}`에서 F5 → 화면 복원. 로그인 화면으로 튕기면 세션 문제이므로 재로그인 후 재확인.
3. **오시작 대비**: 앱에는 되돌리기가 없다(rules 단방향, 403 실증). 잘못 시작하면 **Firebase 콘솔에서 `rooms/{코드}.status`를 `waiting`으로 수정**한다. 콘솔 접근 담당자를 현장에 1명 확보.
4. **진행 정보는 화면 밖에서 관리**: 남은 시간·생존 팀 수는 표시되지 않는다(예시 값). 별도 타이머와 구두 공지로 진행한다.
5. **HTTPS 전제**: 게스트 카메라 권한은 보안 컨텍스트에서만 동작.

## 14. 알려진 한계 (버그가 아닌 현 스펙 — 오탐 방지)

1. **모든 운영 컨트롤이 미연결** — 클릭 시 `운영 컨트롤은 다음 단계에서 연결돼요.` 토스트만. 참가자에게 아무 것도 전달되지 않는 것이 정상(C-02로 쓰기 0건 실증).
2. **방 문서를 구독하지 않는다** — 표시값은 고정 예시(B-03로 실증).
3. **호스트 전용 가드 없음** — 로그인한 누구나 열 수 있다(D-04). 쓰기는 발생하지 않는다.
4. **방 코드 유효성 검증 없음**(D-06).
5. **하단 탭의 판정·기록은 준비 중 안내만**(C-04).
6. **하단 탭 항목 높이 40px** — `BaseSegmented` 기존 스펙(E-02).
7. **뒤로가기로 대기실에 돌아갈 수 없다** — `replace` 스펙(D-02).
8. **운영 화면에서 게임을 끝내거나 되돌릴 수 없다** — `status`는 단방향, 종료 스펙 미구현(G-04).
