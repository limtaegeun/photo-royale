# 프로필·세션 QA Test Case

- **대상**: `/profile` 화면과 그 화면이 여닫는 **로그인 세션**
- **작성일**: 2026-08-31 (서비스 전체 full QA 회차)
- **크리티컬리티**: 오프라인 이벤트 진행 중 — **세션이 끊기면 게임이 붕괴한다.** 화면 자체는 작지만
  이 화면의 로그아웃이 모든 진행 화면(대기실·운영·콕핏)의 전제를 무너뜨릴 수 있어 크리티컬로 둔다.
- **왜 뒤늦게 생겼나**: 화면이 정보 2줄 + 버튼 1개라 기능 문서가 없었다. 그런데 세션 만료·로그아웃
  경로를 다른 문서들이 **전제로만 참조**하고(예: `round-ops.md` D군의 세션 상실, `camera-cockpit.md` H군)
  실제 여닫는 화면은 아무도 검증하지 않았다. 그 공백을 메운다.

## 코드에서 도출한 크리티컬 리스크

1. **진행 중 로그아웃**: 대기실·운영·콕핏을 열어 둔 다른 탭이 있는 상태에서 로그아웃하면,
   Firebase Auth가 브로드캐스트해 그 탭들의 세션도 함께 끊긴다. 각 화면이 이를 어떻게 처리하는지가
   본체다(S-05~S-08). 진행자가 실수로 로그아웃하면 라운드 운영이 통째로 멈춘다.
2. **표시값이 `displayName` 의존**: 닉네임을 Auth의 displayName에서 읽는다(`ProfilePage.vue:11`).
   가입 트랜잭션이 displayName 반영 전에 화면을 그리면 빈 문자열이 보인다(A-03).
3. **되돌아갈 곳이 고정**: 헤더 뒤로가기가 히스토리가 아니라 `entry`로 고정돼 있다
   (route meta `appHeaderBackTo`). 대기실에서 프로필로 들어왔다가 돌아오면 **방으로 못 돌아간다** —
   의도된 스펙이지만 진행 중에 밟으면 방 코드를 다시 입력해야 한다(A-06).

### S-05 — 대기실만 세션 상실을 감지하지 못했다 (수정 완료)

같은 계정의 다른 탭에서 로그아웃했을 때 화면별로 결과가 갈린다.

| 화면 | 감지 수단 | 결과 |
|---|---|---|
| 라운드 운영 | `myId === null` watch (`RoundOpsPage.vue:151`) | ✅ 1초 내 `/login?redirect=…` |
| 카메라 콕핏 | 구독 `onError` → `handleSubscriptionError` (`CameraPage.vue:142·242·248`) | ✅ 토스트 + 진입 화면 |
| **대기실** | **없음** — `subscribeToRoom`/`subscribeToParticipants`에 `onError`를 넘기지 않고(`useWaitingRoomStore.ts:177·182`) auth watch도 없다 | ❌ **조용히 죽음** |

대기실에서 관찰된 증상:
1. 15초를 기다려도 로그인 화면으로 가지 않는다
2. `확인하고 준비 완료`가 그대로 눌리는데 **아무 일도 일어나지 않는다** — 토스트도 없고 명단도 그대로
3. 콘솔에만 `Uncaught Error in snapshot listener: FirebaseError: [code=permission-denied]` 2건
4. 새로고침해야 `/login?redirect=/waiting-room/RQAU`로 간다(라우터 가드는 정상)

**왜 P1인가**: 참가자는 준비했다고 믿고 진행자 화면엔 미준비로 남아, 양쪽 다 원인을 모른 채 게임이 지연된다.
재현 경로가 "다른 탭 로그아웃"이라 드물어 보이지만 **토큰 갱신 실패·세션 만료도 같은 상태**를 만든다.
`waiting-room.md`의 리스크 #1로 이미 예측돼 있던 항목이 실제로 재현된 것이다.

**수정 방향**: 두 참고 구현 중 하나를 대기실에 넣으면 닫힌다 — 라운드 운영처럼 `myId` watch를 두거나,
카메라처럼 구독 `onError`를 넘겨 안내 후 이탈시킨다. API(`subscribeToRoom(code, onChange, onError?)`)는
이미 세 번째 인자를 받는다.

### 수정 (2026-08-31 · `fix/waiting-room-session-loss`)

대기실에도 라운드 운영과 같은 기준을 넣었다 — `WaitingRoomPage.vue`에서 `myId`를 지켜보다가
`null`이 되면 목적지를 보존해 로그인 화면으로 보낸다.

```ts
watch(myId, (id) => {
  if (id !== null) return
  router.replace({ name: 'login', query: { redirect: route.fullPath } })
})
```

진입 시점의 미인증은 `authGuard`가 `whenReady()`로 인증 복원을 기다린 뒤 이미 걸러내므로,
이 watch가 잡는 것은 **화면에 머무는 동안 로그인이 사라지는 전이**뿐이다.

- 회귀 테스트 2건 추가 — 세션이 사라지면 `{ name: 'login', query: { redirect: '/waiting-room/ab2c' } }`로
  이동하고, 세션이 유지되는 동안에는 로그인 화면으로 보내지 않는다.
- 그 과정에서 `WaitingRoomPage.spec.ts`의 auth 모킹을 **반응형(ref)으로 전환**했다. 기존에는 plain object라
  세션 전이 자체를 재현할 수 없었다(그래서 이 결함이 단위 테스트에 잡히지 않았다).
- 수정을 제거하면 추가한 테스트가 정확히 실패하는 것을 확인했다.
