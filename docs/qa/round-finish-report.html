수정 전 재시작 경로가 실제로 무엇을 깨는지

주장에 그치지 않도록 main에서 「라운드 시작」을 실제로 눌러 서버 문서를 전후 비교했다.

[before-restart] assignmentRound=1  round.durationMs=0
                 submissions=[{ status:"pending", round:"1" }]
[after-restart]  assignmentRound=1   round.durationMs=1200000   ← 새 20분이 걸렸는데
                 submissions=[{ status:"pending", round:"1" }]   ← 차수가 그대로라 직전 라운드 미판정 건이 새 큐에 남는다

FIND발견 사항

F-01 · 게스트가 모드 줄을 본다는 설명이 틀렸다

수정 완료
실측
배정된 게스트 화면에 ROOM 카드 자체가 없다(hasROOMcard=false). showGuestAssignment가 참이면 룸 카드가 RoundAssignmentCard로 통째 대체된다.
영향
동작 결함은 아니다 — 게스트는 규칙서에서 모드명을 이미 본다. 다만 코드 주석과 내가 사용자에게 한 설명이 사실과 달랐다.
조치
주석을 실측에 맞게 고쳤다: 이 줄을 보는 건 호스트와 이번 라운드에 배정되지 않은 게스트다.

F-02 · 「먼저 판정하기」가 판정 탭으로 데려가지 않았다

수정 완료
실측
다이얼로그만 닫혔다. 진행자는 하단 판정 탭을 손으로 다시 찾아야 했다 — 라벨이 약속한 동작과 어긋난다.
조치
닫으면서 판정 탭으로 전환한다. 재검증에서 activeTab=judge + 대기 큐 화면 확인.

F-03 · 다이얼로그에서 파괴적 액션이 시각적으로 더 강하다

개선 후보
내용
권장 액션인 「먼저 판정하기」는 외곽선 버튼이고, 「그대로 라운드 종료」는 채운 빨강이다. 위치는 권장이 위인데 색 무게는 파괴적 쪽이 이긴다 — 위 R-05 캡처에서 눈이 먼저 가는 쪽이 빨강이다.
판단
버그가 아니라 디자인 결정이라 손대지 않았다. 기존 「게임을 종료할까요?」 다이얼로그도 같은 색 규칙(파괴=danger 채움)을 쓰고 있어, 바꾸려면 두 다이얼로그를 함께 정해야 한다.

GAP검증하지 않은 것

  • 여러 참가자·여러 팀 규모 — 게스트 1명(1인 팀)으로 전체 체인을 돌렸다. 라운드 종료 로직은 인원 수에 의존하지 않지만(pendingSubmissions.length만 본다), 다인 편성에서의 판정 큐 적체는 보지 않았다.
  • 게스트 화면의 라운드 종료 반응 — 호스트가 종료했을 때 게스트가 카메라에서 대기실로 돌아가는 전이는 이번 회차에서 확인하지 않았다. 기존 gameStatus 스냅샷 경로를 그대로 타므로 docs/qa/round-ops.md가 이미 커버한 영역이다.
  • 2차 배정으로 모드를 실제로 바꾸는 흐름 — 종료 후 「2차 팀 배정」 버튼 노출까지만 확인했다. 다른 모드는 전부 available:false라 지금은 고를 수 없다.
  • 전용 TC 문서 없음 — 이 두 변경은 docs/qa/round-ops.md·waiting-room.md에 없는 신규 동작이라 케이스를 이 회차에서 설계했다. 정식 커버리지가 필요하면 qa-tc로 문서화하는 편이 낫다.
