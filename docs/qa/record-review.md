# 킬샷 기록 열람 QA Test Case

- **기능**: 호스트의 전 라운드 킬샷 제출·판정 기록 열람
- **브랜치**: `feat/p06-record-review`
- **작성일**: 2026-07-26
- **크리티컬리티**: 오프라인 실시간 게임의 운영 기록·사진 열람 기능 — 기록 누락·사진 노출·현재 라운드 오판정은 이벤트 진행에 직접 영향
- **선행 문서**: `docs/qa/photo-submission-judging.md`, `docs/qa/round-ops.md`
- **검증 환경**: local Vite + 실제 Firebase(`photo-royale-scc`, STANDARD/FIRESTORE_NATIVE). `main`에는 기록 화면이 없어 기능 before/after 비교는 불가하며, 인접 판정 UI와 디자인 시스템을 시각 기준으로 삼는다.

## 테스트 환경과 사전조건

- 호스트 1명, 참가자 2명 이상(A/B 팀), 진행 중 방 1개.
- 기록 데이터: 현재 라운드 pending 1건, approved 1건, rejected 1건, 이전 라운드 pending 1건 이상.
- 브라우저: 데스크톱 Chrome CDP + 모바일 뷰포트 320×568, 390×844, 430×932.
- 실제 Firebase 데이터 생성은 계정·방·participants·submissions 문서를 남기는 side effect이며, 생성 즉시 manifest에 계정/uid/방 코드/문서 ID를 기록한다.
- 실기기 iOS Safari/Android Chrome, 화면 잠금 5분+, 60분 체류는 자동화 범위 밖이면 `⏸ 미검증`으로 남긴다.

## 알려진 한계

1. 기록 사진은 Firestore 문서 data URL이며 전체 컬렉션을 구독한다. 페이지네이션·썸네일 분리는 이번 변경 범위가 아니다.
2. 게임이 waiting 상태면 round-ops 화면의 기록 목록 대신 시작 전 안내가 표시된다. 기록은 playing 상태의 호스트 운영 화면에서 확인한다.
3. terminal Listen 오류는 자동 재구독하지 않고 새로고침을 복구 절차로 안내한다.
4. iOS Safari/Android Chrome, 화면 잠금 5분+, 60분 체류는 실기기 증거 없이는 통과 처리하지 않는다.
