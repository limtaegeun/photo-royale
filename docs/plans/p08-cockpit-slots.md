## 0. 한 줄 요약

**MVP는 두 칸 — 기록과 지도.** 둘 다 이미 있는 데이터를 보여주는 일이라 rules 변경은 지도 갈래 하나뿐이다(처음엔 방 문서 `mapImageUrl` 한 줄 → 2026-10-10 `rooms/{code}/assets/venueMap` 문서 갈래로 바꿨다). 아이템 2종(보호막·저격)은 기획자 결정(2026-09-20)으로 **MVP에서 제거**했다 — §2.3·2.4는 나중에 아이템을 넣을 때 출발점으로만 남긴다. 콕핏 하단 격자는 아이템 칸을 지우고 **지도 · 기록 2칸**이 된다.

## 1. 설계 원칙

1. **판정은 호스트가 한다** — 아이템도 참가자가 "쓰겠다"고 선언하고, 효과는 판정·정산 시점에 원장 규칙으로 계산한다. 참가자 기기가 점수를 만들지 않는다(현 모델과 같다).
2. **데이터는 원장 하나** — 새 컬렉션을 만들지 않는다. 아이템 상태는 `rounds/{차수}`(라운드 단위) 또는 `participants/{uid}`(게임 단위)에 필드로 얹고 rules 갈래를 한 줄씩 늘린다. 배포 순서는 rules 선배포 → 클라.
3. **야외·음영지역 전제** — 슬롯은 시트(BaseBottomSheet)로 열고 오프라인에서도 캐시로 읽히는 것만 보인다. 아이템 사용 쓰기는 다른 쓰기와 같이 큐잉되고 latency compensation으로 즉시 반영된다.
4. **모드가 슬롯을 소유** — 모드마다 켤 슬롯이 다르다(스태프 추격전에는 저격이 없다). `GameModeDefinition`에 슬롯 가용성을 적어 콕핏은 읽기만 한다(M4의 `targeting`·`killshotLock`과 같은 방식).
5. **자리만 있는 버튼을 남기지 않는다** — 기능이 없는 슬롯은 숨긴다. 4칸 격자는 있는 만큼만 채운다.

### 2.2 슬롯 3 — 지도 · **P2, 정적부터**

| 항목 | 내용 |
|---|---|
| 목적 | 행사장 경계·안전 구역·집결지를 뛰는 중에 한 번에 본다. 규칙 카드의 "도로 진입 금지"가 지도 위에 보여야 지켜진다 |
| 단계 1 (정적) | 진행자가 대기실 '행사장 지도'에서 **이미지 파일을 골라 올리면**(링크 입력 없음 — 2026-10-10 결정 5 변경) 브라우저가 긴 변 2000px JPEG로 줄여(2000px에서 품질을 0.8→0.6→0.5로 낮춘 뒤에야 1600·1280px로 줄인다, 1,000,000자 이하) `rooms/{code}/assets/venueMap` 문서에 저장한다. 폰 사진은 형식을 가리지 않는다 — 브라우저가 못 읽는 HEIC/HEIF(안드로이드·PC 크롬)는 heic-to(libheif)로 풀고, 해독기는 HEIC를 고른 그때만 내려받는다(2026-10-11). 방 문서와 따로 둔다 — 방 문서는 참가자 전원이 계속 구독해 거기 실으면 방이 바뀔 때마다 지도가 다시 내려간다. 참가자는 입장(참가 등록) 때 받아 두고, 콕핏 시트는 그 지도를 꽉 채워 보인다(오프라인에서도 열린다). 핀치 줌은 브라우저 기본. Storage 없이 간다 |
| 단계 2 (내 위치) | `geolocation` 1회 권한으로 내 점만 얹는다(공유 없음, 배터리 최소). 지도 이미지에 좌표 두 점(네 귀 위경도)을 호스트가 입력해야 하므로 방 설정 UI가 필요 — 규칙서에 지도 준비 절차를 추가해야 해서 기획 확인 대상 |
| 단계 3 (보류) | 팀원·상대 위치 공유는 하지 않는다 — 개인정보·배터리·"사진으로 잡는 게임"의 재미와 충돌 |
| rules | 단계 1: `rooms/{code}/assets/{assetId}` — 읽기는 호스트·그 방 참가자, 쓰기는 호스트만 `venueMap` 문서에 `image`(JPEG 데이터 URL, 1~1,000,000자)·`updatedAt`(request.time). 삭제 없음. 방 상태와 무관(게임 중 쓰기도 허용하지만 진행자 화면은 게임 중 대기실로 못 가서 화면으로는 라운드 사이에만 바꾼다). 처음의 방 문서 `mapImageUrl` 갈래는 지웠다 |
| 문구 | 대기실 행 '행사장 지도' · 캡션 '아직 등록하지 않았어요.' / '등록됨' · 버튼 '지도 등록' / '바꾸기'. 시트 '이미지 고르기' · '저장' · 안내 '참가자 콕핏의 지도 버튼에 이 이미지가 보여요. 핀치로 확대할 수 있는 큰 이미지가 좋아요.' · 읽기 실패 '이미지를 불러오지 못했어요. 다른 이미지로 다시 골라 주세요.' · 저장 실패 '행사장 지도를 저장하지 못했어요. 다시 시도해 주세요.' · 토스트 '행사장 지도를 등록했어요.' |
| 모드별 | 전 모드 켬. 지도가 등록되지 않은 방은 슬롯을 숨긴다 |

### 2.3 (MVP 제외) 아이템 「보호막」 — 후일 참고용

| 항목 | 내용 |
|---|---|
| 효과 | 이번 라운드 우리 팀 **라이프 +1**. 2인 팀은 한 번 잡혀도 살고, 1인 팀은 세 번째 히트에 탈락한다 |
| 사용 | 게임당 팀 1회(참가자 누구나 대표로 누름). 라운드 시작 뒤 잡히기 전까지만 |
| 데이터 | `rounds/{차수}.shields: { [완장]: true }`(라운드 단위) + `participants/{uid}.itemsUsed.shield: 차수`(게임당 1회 근거). `livesOf`가 `shields[완장]`이면 +1 |
| 판정 | 판정 시트의 대상 행에 **보호막** 배지 — 호스트가 "한 번 더 잡아야 탈락"을 안다. 스태프 아웃 시트도 같다 |
| 점수 | 직접 효과 없음(살아남아 생존 5·다음 킬 기회를 얻는 간접 효과). 왕잡기의 왕(X 팀)에게 허용할지가 쟁점 — 왕 보호막은 그룹 −20을 한 번 막는 강한 카드다 |
| rules | `rounds` 갈래에 `shields` 선택 키(map, 참가자 본인 팀 완장만, 값 true, 1회) · `participants` 갈래에 `itemsUsed`(본인만) |

### 2.4 (MVP 제외) 아이템 「저격」 — 후일 참고용

| 항목 | 내용 |
|---|---|
| 효과 | 이 아이템을 켠 채 올린 **킬샷 1건이 인정되면 2배**(일반 10 → 20). 낙오 3배와는 겹치지 않는다(호스트가 3배를 고르면 3배가 우선) |
| 사용 | 게임당 팀 1회. 촬영 전에 켜고, 그 사진의 제출 문서에 `boost: true`가 붙는다. 반려되면 소모되지 않는다(다음 사진에 다시 켤 수 있다) |
| 데이터 | `submissions/{id}.boost: true`(제출자만 쓰는 선택 키) → 승인 시 `multiplier: 2` 허용(`KillMultiplier` 1·2·3) → `tally.{완장}.doubleKills` |
| 판정 | 판정 시트에 **저격** 배지. 호스트는 배율을 고르지 않는다 — 2배는 자동, 3배 토글을 켜면 3배 |
| 점수 | 그룹 동료 킬(+5)은 건수 기준이라 그대로. 왕잡기 왕 사냥(30)과 겹치면 30 유지(저격 소모 안 함) |
| 모드별 | 스태프 추격전 꺼짐(킬 없음). 그 외 켬 |
| rules | `submissions` create에 `boost` 선택 키, update(판정)에 `multiplier in [1,2,3]`, `rounds` 집계 갈래는 map 검사라 변경 없음 |
