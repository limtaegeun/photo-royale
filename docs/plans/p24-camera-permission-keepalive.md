## 0. 한 줄 요약

콕핏을 나갈 때 카메라 트랙을 끄던 것을 바꿔, 같은 방에 있는 동안은 저화질로 쥐고 있다가 다음 라운드 콕핏에서 그대로 다시 쓴다. 방을 나가거나 콕핏 밖에서 30분이 지나면 끈다. rules 변경 없이 hosting 만 배포한다.

## 1. 문제

1. 콕핏(`CameraPage`)은 마운트할 때 `getUserMedia` 를 부르고, 언마운트할 때 트랙을 껐다.
2. 대기실 → 콕핏 전환은 방 스냅샷이 일으킨다(`WaitingRoomPage.vue` 의 watch → `router.replace`). 사용자 탭이 없다.
3. iOS WebKit 은 카메라를 끈 지 1분이 지난 뒤 탭 없이 요청하면 권한을 다시 묻고, 10분이 지나면 탭이 있어도 다시 묻는다(`UserMediaPermissionRequestManagerProxy.cpp`).
4. 그래서 라운드 사이가 1분만 넘어도 매 라운드 콕핏 진입마다 권한 창이 떴다. 2026-11-15 iOS 27.2 시뮬레이터 사파리에서 2회 측정 모두 75초 뒤 재진입에 다시 떴다.
5. 11/08 에 같은 수정을 만들었지만 커밋하지 않은 채 작업 폴더가 정리돼 사라졌다. 이번에 처음부터 다시 만들었다.

## 2. 변경

- `src/features/camera/stores/useCameraStreamStore.ts`(신규): 스트림을 방 단위로 쥔다.
  - `acquire(방)`: 같은 방에서 쥔 트랙이 살아 있으면 권한 요청 없이 1920×1080·30fps 로 되돌려 쓴다. 아니면 새로 요청한다
  - `park()`: 콕핏 이탈. 끄지 않고 640×480·5fps 로 낮추고 30분 뒤 끄기를 예약한다
  - `release()`: 끈다. 권한 응답 전에 놓았으면 늦게 온 스트림도 끈다
  - 쥔 트랙이 OS 회수 등으로 끝나면 버리고, 콕핏 안이면 재시도 UI(error)를 띄운다
- `src/features/camera/composables/useCameraStream.ts`: 스토어를 빌려 쓰고, 스코프 해제 시 끄지 않고 `park()` 한다. 방 코드를 인자로 받는다
- `src/features/camera/composables/useCameraRoomGuard.ts`(신규) · `src/router/index.ts`: `router.afterEach(releaseCameraOutsideRoom)` — 다른 방·방 코드가 없는 화면으로 가면 끈다. 막힌 이동은 무시한다
- `src/features/camera/CameraPage.vue`: `useCameraStream(roomCode)`

## 3. 검증

- 정적: type-check, lint, vitest 통과(main 병합 뒤). 새 테스트: 스토어 20 · 라우트 후처리 7 · composable 3 · 콕핏 재진입 1
- iOS 27.2 시뮬레이터 사파리(Web Inspector 가짜 카메라 + XCUITest 가 권한 창을 눌러 센다): 이 브랜치의 스토어를 번들한 측정 페이지로 진입·이탈·방 이탈을 탭 없이 흉내 냈다
  - 수정 전 호출: 75초 뒤 재진입에 권한 창 다시 뜸(2회 측정 모두)
  - 수정 후: 75초·30초·11분 뒤 재진입 모두 권한 창 없음. 방 이탈 뒤 75초에는 다시 뜸(대조군)
  - 측정 중 찾은 결함: 되돌릴 때 프레임률을 적지 않아 콕핏이 5fps 로 남았다 → `frameRate: { ideal: 30 }` 추가 후 30fps 확인
- 크롬 실앱(Firebase 에뮬레이터 · 진행자·게스트 두 브라우저 · 가짜 카메라): 게임 두 판 동안 카메라 요청 수정 전 2회 → 수정 후 1회(같은 트랙), 대기실 640×480·5fps 유지, 프로필·다른 방 이동 시 끔, 30분 경과 시 끔, 재진입 뒤 킬샷 1920×1080 제출, 권한 거부 → 다시 시도, 진행자 화면 카메라 0회
- 홈 화면 4분 다녀온 뒤 재진입: 수정 전 권한 창 다시 뜸, 수정 후 뜨지 않음

- 배포 뒤 확인: 배포본 `index-BkPkwnNI.js` 가 머지 커밋 빌드와 같고, 콕핏 복귀 제약(`frameRate: { ideal: 30 }`)이 들어 있다. 실서버에서 게임을 돌려 보지는 않았다

## 4. 후속 — 대기 중 자원 최소화 (2026-11-15)

사용자 요구: "더 낮춰서 배터리와 휴대폰 성능에 부하가 안 가게, 정말 최소한의 리소스를 쓰도록".

- 대기 제약을 640×480·5fps 에서 320×240·1fps 로 내리고(ideal 이라 기기가 못 맞추면 가장 가까운 값), 쥐고 있는 동안 트랙을 끈다(`enabled = false`). 콕핏에 들어가면 트랙을 켜고 1920×1080·30fps 로 되돌린다
- iOS 27.2 시뮬레이터 사파리 실측(이 브랜치 스토어 번들 측정 페이지):
  - 대기 중 320×240·1fps · 트랙 꺼짐 · 스트림 live
  - 75초·30초·11분·홈 4분 뒤 재진입 모두 권한 창 없음. 방 이탈 뒤 75초에는 다시 묻는다(대조군)
  - 재진입 뒤 고화질 첫 프레임: 56~65ms. 기존 640×480·5fps 방식 53~62ms 와 같은 수준이다
- 크롬 헤드리스(가짜 카메라)에서도 같은 스토어로 진입 → 이탈 → 재진입 두 번: 대기 320×240·1fps·꺼짐, 재진입 60ms 안에 1920×1080 프레임
- 배터리 절감량은 시뮬레이터로 잴 수 없다. 실기기에서 대기실 30분 배터리 소모를 비교해야 안다
- 배포 뒤 확인: 배포본 `index-BB_eGSEW.js` 가 머지 커밋(208ee45) 빌드와 같고, 대기 제약(`width: { ideal: 320 }, height: { ideal: 240 }, frameRate: { ideal: 1 }`)과 트랙 끄기가 들어 있다. 실서버에서 게임을 돌려 보지는 않았다
